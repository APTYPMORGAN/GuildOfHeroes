## Защита состояния в классе `Game`

1. **Выбранное правило:** 
   Рейтинг игры (`Rating`) всегда должен находиться в допустимом диапазоне от `0.0` до `5.0` включительно. Изменить его напрямую извне класса нельзя (`private set`).

2. **Где оно проверяется:**
   * **В конструкторе `Game`:** проверяется переданный начальный рейтинг `Rating`. Если значение меньше `0.0`, оно приводится к `0.0`; если больше `5.0` — приводится к `5.0`.
   * **В методе `AddRating(double amount)`:** перед расчётом среднего рейтинга проверяется новая оценка. Недопустимые значения (`amount <= 0.0` или `amount > 5.0`) отклоняются, и состояние объекта не меняется.

3. **Входные и фактические значения при неправильном действии:**
   * **Создание объекта с превышением границы:** на вход в конструктор передан начальный рейтинг `99.0` -> фактическое значение `Rating` после создания составило `5.0` (приведение к верхней границе).
   * **Добавление отрицательной оценки:** при текущем рейтинге `3.5` вызван метод `AddRating(-2.0)` -> фактическое значение `Rating` осталось `3.5` (действие отклонено).
   * **Добавление оценки выше максимума:** при текущем рейтинге `3.5` вызван метод `AddRating(10.0)` -> фактическое значение `Rating` осталось `3.5` (действие отклонено).

Класс `Game` — карточка игры в магазине (название, жанр, год, средний рейтинг и количество на складе).

**Какие данные защищены и почему:**

Свойство `Name` работает через закрытое поле `_name`. В `set` проверяется, не пустая ли строка и нет ли лишних пробелов.

**Что проверяют конструктор и методы:**
* Конструктор ставит начальные нули для рейтинга и количества, обнуляет год, если он `<= 0`, и чистит имя через свойство `Name`.
* `AddRating` принимает оценки только от `0` до `5.0`, остальные игнорирует и считает средний рейтинг через закрытые поля `_count_rating` и `_all_rating`.
* `AddAmount` прибавляет количество на складе, только если число больше нуля.

### Защита состояния Game (подробно)

**Почему методы ПР №2 не защищали от прямой записи в поле:**
Потому что поля были `public`, и в `Program.cs` можно было написать `Witcher.Rating = 999` в обход методов.

**Чем отличаются get, set и private set:**
`get` — можно читать, `set` — можно менять всем, `private set` — менять можно только внутри самого класса `Game`.

**Где проверяется начальное состояние:**
В конструкторе `Game` при создании объекта, а имя проверяется в `private set` свойства `Name`.

**Как методы сохраняют границы:**
В `AddRating` стоит проверка `if (amount <= 0 || amount > 5.0) return;` — кривые оценки просто отбрасываются. В `AddAmount` стоит `if (amount <= 0) return;`.

**Как Name использует поле `_name` и значение `value`:**
В `set` приходит `value`. Если оно пустое (`IsNullOrWhiteSpace`), в `_name` записывается `"Без названия"`, иначе `value.Trim()` без пробелов.

**Почему в конструкторе используется `Name = name`:**
Чтобы сразу сработала проверка из `set` и убрались пробелы, а не записалось напрямую в `_name`.
